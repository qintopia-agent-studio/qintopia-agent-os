## 3. 修复与测试是否解决了实际问题

**过期游标 HTTP 410 被转换成 500：已修复。**原函数报告游标失效，但路由错误 schema 不接受
`rebuild_required`，实际 HTTP 因序列化失败返回 500，Agent OS 无法识别重建要求。

联调分支为该端点 410 增加精确响应定义，保留其他错误和鉴权约束；新增真实 HTTP 状态及 JSON 断言。J16 进一步验证接收端进入重建、保留检查点并保持禁发。源码修复与结果相符。

**原迁移新安装被启动指纹检查拒绝：已修复。**修复精确接受两个已有来源的结构指纹，未知指纹仍失败关闭，后续角色、结构和触发器校验保留。增加受限 runtime 就绪、关闭关键触发器后拒绝、恢复后通过的回归。

这不等于本轮重新核验了生产数据库。目标数据库版本仍须在发布前核实。

**A 后续迁移兼容回归已完成。**对保留的 v2 合成库运行真实迁移器，检查旧迁移 checksum 及 16 张欢迎表的数量和完整内容 hash 不变。

随后验证全新安装、真实签名投递、pull 去重、消费修订与重建入口。4/4 通过，原待办关闭。

## 4. 能证明什么

- PMS 的事件投递与增量读取可进入同一 Inbox 去重；ACK 只表示接收，不表示业务已完成。
- 重复、乱序、回执丢失和断网重启有恢复证据；冲突不会静默覆盖原记录。
- 游标过期、分页失败和重建代次有受控恢复；成员/库存失效、恢复及跨营业日安排能够收敛。
- 历史补录、补偿和重建不会因此自动取得欢迎准入；本次效果计数保持零。

最后一项仅证明已测试的接收与恢复门禁。测试没有配置完整申请、真实授权和发送适配器，不能据此认为完整欢迎 T01—T16 或全部发送风险已验收。
