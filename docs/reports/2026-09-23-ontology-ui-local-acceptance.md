## 实现与约束

| 使用者需要判断的事     | 页面与服务实现                                                                                 |
| ---------------------- | ---------------------------------------------------------------------------------------------- |
| 谁负责、何时开始       | 任职支持未来开始与明确截止；尚未开始明确显示没有可执行权限，更新时保留原开始时间               |
| 工作受什么约束         | 岗位详情引用当前适用的已确认规则、来源、确认人、版本、范围及有效期，包含共享上层约束           |
| 账号是否属于本人       | 人员详情列出可信来源已有候选，预览核对后确认或撤销；共享账号、未观测来源及命名空间冲突拒绝关联 |
| 撤销会影响什么         | 展示会话、任职和委派影响；最后核验撤销后旧权限失效，重新核验不恢复旧权                         |
| 智能体现在能否执行     | 分开显示登记、当前范围配置、本地执行器与真实渠道；合成本地能力不冒充真实模型上线               |
| 实际覆盖哪些人         | 同一服务解析本范围当前、过往、明确选择与待确认人员；去重并在执行前重新核验                     |
| 谁修改了什么           | 变更记录展示操作者、时间、前后内容及影响；旧记录缺失的信息明确标注                             |
| 启用账号为何仍不能登录 | 只读显示当前身份与人员状态的登录限制，重置密码不解除身份限制                                   |

身份写入复用密码会话、身份管理权、配置/来源/Gateway 三重版本校验和幂等回执。浏览器不能提供操作者、命名空间或核验证据。旧欢迎身份入口同时失效已派生的组织身份投影，避免残留权限。

动态名单只接纳可信范围内的实际入住依据；过期、冲突、空楼栋、未确认及共享身份保持未知，不归入过往住客。006 保存按楼栋的实际入住观测历史；旧记录仅回填已记录的最后楼栋。007 追加幂等安装与 schema 登记，保留已应用 006 的 checksum。迁移与恢复详见[数据设计](../../runtime/postgres/docs/data-design/2026-09-23-ontology-audience.md)。
