# PR #704 根规则删减评估

审查对象：PR 原始提交 `6e6250ee`，集成基线 master `adb29207`。

## 决定

本次撤销 PR 的根 `AGENTS.md`
重写，保留 master 原文。精简根入口的方向合理，但原补丁不能作为已验证的无损整理单独合并。此次只接受本地人员与欢迎基础，不把工程规则重构作为它的依赖。

原 PR 对根文件增加 126 行、删除 1,991 行，最终约 130 行。新版本保留了领域目录、Postgres 权威、最小权限、脱敏、生产默认关闭、文档先行等一般原则，比旧文件容易阅读。但“专项 runbook 为准”不能替代被删除规则的明确去向。

## 合理与不合理的删减

| 类别                                        | 判断与处置                                                                                           |
| ------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| 大量固定命令、环境变量与历史部署记录        | 不适合长期占据根入口；应移到已有运行手册并链接，不能只删掉                                           |
| 重复的包归属、提交、验证、生产边界原则      | 可归并；保留具体运行入口和最具体规则优先关系                                                         |
| 发送不确定性、claim 清理、审批与版本绑定    | 是防回归约束，不是操作噪声；必须保留到对应模块规则、测试或明确文档                                   |
| CI 工具安装方式与精确版本、测试隔离约束     | 属于可执行工程契约；不能以“按风险验证”概括后丢失                                                     |
| Release 顺序、当前 master 校验、PR 审查处理 | 通用“不绕过审批”不足以覆盖这些具体门禁，必须逐条映射                                                 |
| 服务器连接资料边界                          | 原重写称从清单取端点和密钥路径；当前 master 明确资料不在仓库、向管理员获取，且禁止搜索私钥。不能回退 |
| Agent OS 身份、组织与 PMS 新原则            | 与功能设计一起留在包文档；不应趁恢复历史成果覆盖整个仓库运行契约                                     |

具体反例：当前 master 的“unknown 不自动重发”、生产 Huabaosi/QiWe 分离构建、真实回调可信来源、全测试栈大小及 Release 手动审查都有细粒度约束。原补丁虽然保留其中一部分抽象原则和少量字符串检查所需片段，却没有列出其余约束迁移到哪个文件、哪条测试。静态部署检查通过只证明当前检查器匹配，不能证明没有知识丢失。

## 后续独立拆分的验收标准

建议另一次规则整理采用无损移动，而非直接复用原 PR 的替换文本：

1. 根文件保留项目地图、启动协议、全局不变量和验证入口。
2. 按身份/授权、发送、部署、CI 等领域将其余条目映射到包级规则或工程文档。
3. 为每个移动或删除的条目列出原条目、目标路径与理由；仅有测试的条目也要说明测试保护的行为及剩余人工规则。
4. 同步更新读取根文件的契约检查器，验证根索引链接和迁移清单；不能仅补回若干关键字符串让旧检查变绿。
5. 单独评审规则语义不变、各目录代理能够找到适用规则后再合并。

本次未提交一个仍有规则丢失风险的“拆分 PR”。规则重构无需阻塞 #704 的本地功能整合，恢复主线即可解除这项风险。
