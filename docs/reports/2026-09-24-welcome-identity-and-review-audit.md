## 自动关联结论及最小后续路线

本次证明了稳定渠道账号有可用接口基础，但没有证明“进群账号 → 申请 →
PMS 逐个实际入住人”的可靠完整关联。不能报一个未经计算的成功率，也不能用候选相似度代替可靠身份。

建议后续依次验证，具体新接口、来源写入和生产配置按各自授权实施：

1. 查明当前 QiWe 转换入口的受支持接法；优先现有能力，不为一次测试改基础设施。核对企业/应用作用域，使用真实返回的账号映射复测一栋、二栋。
2. 核查已有 `follow_user.state`
   的来源和语义，检查原申请入口是否曾保留可信渠道引用。现有样本仅证明 state 存在，不证明它包含申请关系；没有依据时不猜测。
3. 若历史证据确实不足，在正常申请或接待数字入口自动携带经过验证的渠道账号，并关联申请及 PMS 逐人入住引用。可评估同一开放平台下的微信登录与 unionid 对接；属于待验证方案，不承诺现有飞书表单天然提供此能力。仅发送专属链接不能证明填表人就是目标账号，仍须可信登录/回调上下文。
4. PMS 输出住宿事实与来源引用，Agent
   OS 维护共同身份、任职、任务和确认记录；不要求工作人员再建一份人员台账。同行人、代付、换号、多人共用账号及歧义分别保留状态，不能为提高覆盖率误合并。
5. 入群事件触发欢迎处理，尚未建立可靠关联时停在“暂未对应入住资料”，不得展示别人的卡片或自动发送。实际入住、内容许可等既有条件仍须满足，除非用户明确改变该业务规则。

## 欢迎公共入口最小接线提案

本节供两条开发线确认接口语义，不是已实现 API 或新的 PMS 执行协议。

总指挥任务 `01a0c6ee-1de7-7302-8be1-3f7966f51bea`
于本日转达用户新决定：每笔登记收款必须有人确认，长期授权不能替代；原完整明确指令可作为当笔确认，不重复询问。PMS 主动向 Agent
OS 发送收款事件；事件发送和 head 接口由 Green
PMS 项目承担，岸岸负责接收和处理。该决定不改变欢迎内容确认与 PMS 业务确认分离，相关跨仓接口仍由对应任务负责。

| 边界       | 最小约束                                                                                                                                                    |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 输入       | 可信来源事件/任务引用与版本、幂等键、物业/楼栋范围、已核验 Person/逐人住宿引用；卡片产物及文案版本、展示许可依据。缺失身份可保存待关联事项，不进入确认/发布 |
| 服务端解析 | 从可信会话、岗位任期与授权解析岸岸身份、当前确认者和目标群；不得接受模型自报审批者、权限或群名作为执行依据                                                  |
| 输出       | 同一个持久事项引用、当前状态、等待原因、内容版本及配置版本，供群与 UI 展示；内部 ID 不作为用户辨认人的方式                                                  |
| 确认效果   | 有权客服或主管确认“该人、住宿、介绍、卡片对应正确”；只推进欢迎内容/资格阶段，不代替 PMS 订房、收款、入住确认，不等于发布成功                                |
| 版本与并发 | 确认绑定卡片和文案版本；改版使旧确认不能用于新版本。群与 UI 同时办理只产生一次有效状态迁移；迟到的旧消息不能批准新版                                        |
| 权限与恢复 | 每次动作重新检查任职有效期、范围、撤权和当前配置；无人有权则保留待处理。发送结果未知保留 UNKNOWN，不自动重发；恢复沿用原事项和幂等键                        |

UI 提供业务可读的“谁可以确认”“发到哪个工作群”，支持查找人员、选择岗位任职范围及生效期限。群显示名称与可靠渠道标识绑定，不要求用户填写裸 ID。配置变更应明确待办受影响范围；不能把所有历史任务静默转发到新群。

群中以岸岸发出的具体事项卡片/引用作为确认对象；普通无指向的“同意”不能误批其他人或其他版本。内容修改和停止也要指向同一事项。工作群呈现的是获准用于该确认的卡片、文案与必要信息，不包含身份证号等无关住宿资料。
