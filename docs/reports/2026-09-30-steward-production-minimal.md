# 舍长与二花共享服务最小接入

本轮实现可配置的人员／工作账号／渠道／群候选，以及二花读取和维护本栋知识的共同服务。UI 与可信工具使用同一份任职、授权、知识版本与 WorkItem。完整欢迎和入住匹配未纳入本批。

分支：`codex/steward-production-minimal`。基线：`74899d4191b810bc0cf5dc748c742c3b84aea0b5`。本报告随实现提交；最终提交和 PR 在交付消息中回报。

## 范围与实现

- 新增 `/api/workspace/candidates`，沿用登录、当前 Policy 与租户事务锁。
  `people`、`accounts`、`channels`、`groups`
  分别查询，姓名、昵称和渠道供人辨认，引用只供内部办理。每页最多 50 条，支持完整目录续页与搜索，不截断前 256 人；翻页时重新核验权限。
- 按 `assign`、`delegate_review`、`contact`、`set_groups`
  采用已有权限。临时审批代理要求本栋当前在住，普通任职不新增在住限制。工作账号与自然人分别返回；同一人的多个已登记渠道可分别选择。
- 候选入口区分 400 参数错误、401 未登录、403 无权、503 来源不可用和 200 无匹配。已绑定但停用、重建中、当前解析器不支持的真实 PMS 来源及失效住宿投影不能伪装成空居民名单。
- 正式知识／规则／临时代理 HTTP 与网页例句分别控制。 `/api/state` 的
  `foundation_available` 与 `dialogue_available` 分开；服务可用不等于 Hermes 已接通。
- 二花沿用现有插件注册入口，仅增加默认关闭的生产最小工具白名单。群消息按当前唯一群绑定确定楼栋，私聊按唯一有效二花任职确定范围；多范围返回待澄清。身份、任职、群绑定与授权变更在后续调用和执行时再次核验。
- 可信消息的来源必须已登记为认证原始事件；变更引用服务端返回的消息
  `operation_id`。群内不返回个人身份背景或私人历史。生产 broker 核验不同 runner 用户、socket 目录与权限、token 摘要及批准的数据库 URL 摘要。

没有新增迁移、角色体系、生产授权、Profile 配置或部署机制。PR `#731`
的客房通信选择保持原语义；前端由现有 UI 任务消费本轮共享契约。

## UI 接入与操作验收

按[共享接口 v1](../plans/active/steward-workspace-completion.md)接入，需保留以下区别：

- 工作人员搜索并选人安排任职；临时代理通过在住候选查询，不复用完整人员目录。
- 联系候选按当前 Audience 返回；群配置仍要求现有社区根管理权。
- 正式知识支持保存、修改、停止和重新启用；应回读对应知识版本与服务回执。
- 生产代理状态 `candidates=null`、`candidate_query_required=true`
  表示需要分页查询，不表示无人。
- `foundation_available=true`、`dialogue_available=false` 时仍允许按权限维护知识和约定。

人工验收须观察“舍长交代 → 二花调用实际工具 → 页面回读相同版本 → 更正／停止／撤权后生效”。目前未验证真实 Hermes 模型和微信／企微入口，不能仅凭本地检查宣布线上闭环完成。

## 生产与恢复边界

本批没有合并、发布、部署、连接生产数据库、发真实消息或赋真实权限。未来启用需审阅运行参数与实际用户隔离，沿用现有发布机制；门禁不替代部署授权。

实际不同用户进程的正向 broker 验证尚未完成。本机验证了权限契约及同用户拒绝；早期 Docker
daemon 不可用，最终 test:doctor 已确认可用，但本轮未执行不同用户的正向联调，也未创建系统用户或调整基础设施。完整真实 PMS 在住投影、未关联账号识别、入住模糊匹配与工作群人工确认由后续业务接入完成。候选 API 只能展示已有可信关联，不自行按姓名或昵称建立身份。

工作目录沿用任务专用 `steward-production-minimal`。根目录未提交规格、前台互动草稿、旧
`foundation-production-bridge`
索引和恢复资料原样保留。Git 原对象由唯一修复任务恢复后已核验闭包；本批没有重置、清理或修复其他工作目录。本任务两套临时 PostgreSQL（64192 和原受支持测试端口 5432）均已正常停止；各自数据、连接说明和日志原样保留用于恢复和验收。
