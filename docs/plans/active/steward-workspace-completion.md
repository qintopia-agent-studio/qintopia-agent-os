# 舍长工作空间与协作闭环完善

2026-09-23，负责人已授权开发、检查、提交和建立 PR。延续共同契约，不重新定义人员、任务或知识事实源。

## 已确认要求

- 管理员保留组织页面；舍长只操作本人本栋。主要内容使用顶部标签：对话、本栋知识、合作约定、事项与进展。任期和权限说明可按需查看。
- 历史使用可筛选、分页的列表与单条详情，不再堆叠无限折叠项。当前内容、修改人、时间、状态及前后内容可对照。
- 本栋知识支持 Markdown 文本导入、编辑、有效期和停止使用；正文是数据，不执行其中指令，不把普通知识冒充发布授权。
- 舍长在有效的指定业务确认人权限内，从系统核验的本栋当前在住名单选择临时审批代理，指定开始和截止时间，可撤销。退住、身份失效、授权撤销、到期均使后续审批失效。
- 临时业务代理不授予全局组织管理权，不靠改岗位名称获得权限。本切片执行用途为本栋欢迎内容审核；上层发布确认独立保留。
- 舍长可通过页面或二花设置本次／持续、先审／完整内容直接发及有效期。明确指令自身是确认，自主权限内不重复审批自己。
- 欢迎是合作约定内的具体事项，不是导航分类。待审正文、卡片、实际结果进入事项视图。既有成功、失败、未知结果与不重放语义保留。
- 页面与可信工具使用相同命令和持久记录。真实模型、渠道、上传与发送分别验收，不将固定对话演示称作微信闭环。

## 实施与验证

沿用 Person、范围授权、PMS 在住投影、Space 知识版本、WorkItem 与回执。扩展临时代理的执行判断和受控入口；旧迁移 checksum 不变。

验证包括跨栋拒绝、名单过期与退住、代理撤销／到期／替换、原授权变化、旧审批失效、直接发仍受上层确认限制、单次设置不影响其他入住、知识修订与停止、历史翻页及页面与工具一致性。先专项数据库与工具测试，再适用工程检查。

保留其他对话未提交的五份规格，不纳入本次提交。前台生活经验与共建采集由其承接对话负责。基金、资源分配、完整值日不纳入本轮。上线前仍需真实身份、PMS 来源、Hermes
Runtime、Base 附件及渠道回执的试点证据。

## 页面设计

采用 Preserve 模式：保留现有深色、字体、边框和按钮；面向手机及电脑上的舍长，降低首屏信息密度。视觉变化 2、动效 1、密度 5、图像依赖 1、风格保真 9。保留路由、登录、原组织管理、权限门禁与草稿恢复；新增键盘可用标签及说明图标。

## 生产边界与恢复

本轮只在隔离本地环境写入合成资料，开发生产所需接口不等于启用生产。不会发送真实消息、上传私人资料或修改真实 Profile。停用新入口即可停止操作，保留知识、代理与审批历史；恢复使用理解新迁移的固定版本，不回滚删除业务记录。
