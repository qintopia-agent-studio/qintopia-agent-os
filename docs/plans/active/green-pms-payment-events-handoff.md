## 业务结果

Green PMS 发现并保存一笔有效新收款后，主动向 Agent OS 发送收款事件。Agent
OS 接收并保存，交给岸岸查询订单、提出匹配建议。有权的人确认具体流水、金额和订单后，岸岸才登记收款；完成后读回实际结果。

每笔登记收款都必须有人确认。已有完整明确指令可作为当笔确认，不要求人重复确认同一效果；岗位权限、长期授权或到账事件不等于这次人的确认。收款不证明到店，不自动办理入住。

## 实施边界

先落实已确认的
[只读事件头接口](anan-payment-feed-baseline-proposal.md)。该切片列明五个 PMS 文件，无须新增迁移；不要把五文件限制误套到新增主动投递的全部工作。

主动投递部分先核对双方现有入口，给总指挥与岸岸任务一份最小版本契约：来源实例、物业、事件 ID、支付事件序号、类型、流水引用、签名及持久接收回执。选择兼容扩展或独立支付信封，保持旧人员/住宿协议、事件字节及原回归有效。确定后由两边分别实现，不新增消息中间件产品。

发送只能针对已提交的持久事件；不得在财务事务尚未提交时先发网络请求，也不得依赖进程内临时队列保存唯一消息。收到接收方持久保存的确认才记为送达；回执丢失允许重发同一事件，接收方不重复创建事项或登记收款。

主动通知与补拉必须使用同一事件身份。乱序到达时不能因收到较大序号就跳过中间缺失事件；首次基线原子保存、重启不覆盖、补拉和发送重试不丢不重。来源变化或序号回退显式处理。

已有 `MATCHED`
或历史流水不再次唤醒新催办；事件到达与实际使用之间仍须回读 PMS 当前状态。事件数据不能充当人员确认或写入授权。

只读接口与通知组件的本地开发不改订单、计价、库存和资金业务含义。新增投递若需要最小持久状态迁移，由 PMS 项目提出并按迁移规则实现；不改写已应用历史迁移。原有 CI 保护、发布、服务器及真实外发门禁继续有效。

## 必要验证与联合交付

- 接口：空流、长历史、权限和物业隔离、bigint 字符串；采样前开始而采样后提交的事务不漏事件。
- 发送：事务回滚不通知；提交后崩溃可恢复；超时、回执丢失、重复和乱序不丢不重；认证错误不会无限错误发送。
- 接收：签名/来源/物业错误被拒绝；持久化失败不返回成功回执；推送与补拉汇合到同一事项，缺失序号可补齐。
- 业务：无当笔人的确认绝不登记收款；确认后仅登记一次；已人工登记则回读已有结果；款项变更或换订单不能复用旧确认。
- 回归：既有人员/住宿事件、资金匹配事务及欢迎链的相关不变量保持。隔离数据库与 PMS 原测试锁并用，记录实际 PostgreSQL 和两仓提交版本。

PMS 侧交付独立 commit/PR、实际验证及接收契约；Agent
OS 提供匹配版本的接收验证，再联合验证“新收款→通知→岸岸建议→人确认→登记→读回”。未启用真实渠道时明确写本地模拟验证，不宣称生产已接通。

## 2026-09-24 发送方接线核对

发送方已提出独立 `pms.payments.v1`
信封，接收方核对现有入口后确认以下兼容边界；实现和联合验证尚未完成。

- 复用固定 `POST /api/v1/ingress/pms/events`，保留旧 `pms.events.v1` 解码和回归。
- 使用
  `X-QT-Key-Id`、`X-QT-Sent-At`（Unix 秒）、`X-QT-Delivery-Id`、`X-QT-Signature`。HMAC-SHA256 原文为方法、路径、时间、delivery
  ID、原始 body 的 SHA256，各段以换行分隔；签名为小写 hex。
- 支付 body 使用 camelCase：`schemaVersion`、`sourceInstance`、`propertyId`、`eventId`、
  `sequence`、`billId`、`kind`、`eventType`、`occurredAt`。sequence 保留规范非负 bigint 十进制字符串；其余事件字段与分页接口相同。
- `kind` 为 COLLECTION / REFUND；`eventType` 为 DISCOVERED / MATCHED；事件 ID 为
  `payment:{billId}:{eventType}`。推送和补拉共享此身份。
- 现有签名边界保持：Content-Type 恰为
  `application/json`，拒绝 Content-Encoding，body 最多 65536 字节，递归拒绝重复 JSON
  key，时间窗口为正负 300 秒；key 固定绑定来源及物业白名单。
- 事务提交后返回 202 `{event_id,status:'accepted',receipt_id}`；同事件同内容重试返回200
  `{event_id,status:'duplicate',receipt_id}`，回执 ID 相同。内容冲突或持久化失败不返回成功。
- 可信去重域为
  `sourceInstance + propertyId + schemaVersion + eventId`。推送和补拉抽取相同事件字段比较内容，外层原始 JSON 字节哈希仅用于签名，不用于跨通道去重。
- 较大序号的推送不能推进连续补拉 checkpoint。MATCHED 先到后旧 DISCOVERED 不新建催办；REFUND 不作为收款使用；使用事件前仍需读回 PMS，任何事件都不替代当笔收款确认。
- 发送方对 401/403 暂停，对 400/409/413/422 进入死信，其余可恢复故障有限重试。联合用例覆盖 push/feed 两种顺序、变化的 delivery
  ID、异内容冲突、乱序、跨来源及物业隔离。

真实本地接收服务的启动命令、模拟配置、两仓提交和联合验证结果由实施报告补充；未就绪前不报可用端口。
