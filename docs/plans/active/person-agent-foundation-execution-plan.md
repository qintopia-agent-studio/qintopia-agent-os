## 3. 本体模型先明确关系，字段按实际使用补齐

2026-09-22：负责人认可先核对人员、渠道身份、任职、工作范围、业务规则和工作事项，再以二花验证同名不误认、跨栋不越权、离任后失效。具体对照、源码依据和接入缺口见[社区业务模型](../../agent-os/community-business-model.md)。这是本节的增量映射；文档完成不代表二花完整对话或生产接入已验收。

“以本体思维建模”在这里是明确对象、关系、事实来源、有效期与权限；不预设引入知识图谱数据库，也不要求先收集一个人的全部资料。

需要先对齐的骨架：

- **自然人与渠道身份**：稳定 Person，多个名称和账号，身份待确认、关联、撤销、合并与历史；工作账号不等于自然人。
- **组织与工作责任**：组织、上下级岗位、职责、任职、管理授权；岗位可以暂缺人员，一人可以担任多个岗位。
- **智能体与触达范围**：智能体登记与运行接入、群及渠道身份、个人或动态人员集合、工作连接及动作权限；同一智能体在不同楼栋分别受限。
- **业务事实**：申请、实际入住人和住宿安排、群成员关系分别来自飞书、PMS、渠道；人员库不以有申请为准入条件。
- **背景与知识**：可使用的事实或偏好、来源、同意范围、更新时间、失效与撤回；模型推断和工作人员确认不能混作客观事实。
- **工作推进**：Event、WorkItem、Artifact、审核及执行回执，用来把上述关系用于具体工作。

这些多数已有表、模型或契约。开发前只做增量映射：已实现可复用、需要调整、尚待验证。每个概念不强制新增一张表；明确已有数据的来源和链接即可。个人事实、任职、住宿和群关系保留各自时间，不把它们覆盖进 Person 的几个当前标签。

负责人进一步确认：Agent
OS 关联人员多维全貌，各 Gateway 共用身份解析；正式智能体协作经过 Agent
OS，负责人可以通过 default 或获授权管理智能体分派工作。详细约束统一见[共同契约 §5.4](unified-person-welcome-v1-contract.md#54-人员全貌管理智能体分派与跨-gateway-身份负责人确认2026-09-11)，本文件不另定义授权或映射协议。

### MVP 上下文读取实施决定（负责人确认，2026-09-22）

当前优先实现效率：**通过受控服务按需直接查询数据库，关键动作执行前重新校验**。UI 保存职责后，后续业务查询读取已提交的有效状态；一次集中取得本轮必要背景，同轮可复用。

## 4. 实施顺序与验收

### 第一步：把已认可结构映射到现有模型与接口

由 Agent
OS 开发任务承接，先列本次新增要求的增量差距：组织上下级、全域管理与本栋自治、独立群台账、对象生命周期、具体群和个人触达。核对现有 Person、职责和连接服务后补足必要契约，不重复全面盘点或重做已完成测试。

验收：用合成案例表达刘珊管理社区服务、两栋舍长分别配合二花、一人多岗、舍长更换和待确认渠道身份。每个关系有来源、范围和有效期；明确哪些现有代码直接复用。权限仍保留自主、需指定人确认、未授予三种状态，不能受简化示意限制。

### 第二步：将组织、台账和配置做成可持久使用的工作台

复用已有本地工作台和服务，按已认可结构调整入口；实现当前切片确实缺少的新增、查询、任职更换、解除关系及停用影响预览。同步接好服务端操作者认证与授权检查，不能把浏览器选中的名字当操作者身份。

验收：按姓名选择已核实候选，保存后刷新及重启仍正确；上下级和本栋范围清楚；换人收回旧任职权限；解除一栋关系不影响二栋；配置变更有版本冲突保护及审计。隔离测试身份通过不等于真实生产登录已验收。

界面另按确认稿做同主题、同视口的实际视觉与操作路径对照。开发者应修正明显偏离，并向负责人提供可运行页面；技术测试、保存成功和无横向溢出均不能替代负责人对视觉及流程的验收。

### 第三步：接通身份来源，并让一个智能体真正消费配置

按最小字段接入申请、PMS 引用、QiWe/企微身份及群成员来源，核实转换的命名空间和账号适用范围。先用合成来源与测试适配器，再按单独授权做受限来源验证。不把“入群”当“已找到自然人”。

实际业务必须解决的身份歧义沿用原有确认路径；可选人物记忆的关联歧义保持未知或受限候选，不为完善画像转人工核实，也不阻塞其他已获准业务。

以二花的本栋知识和工作约定为首个配置消费者：查询当前负责人、读取获准背景，指导或确认形成有版本的结果；需要等待或交接的工作复用 WorkItem。实际工具在执行前重新检查当前授权，而不是只在设置时检查。

分层知识按[业务模型 §9](../../agent-os/community-business-model.md#9-社区楼栋与领域知识的分层维护)复用既有范围和知识版本设计。

最小切片使用社区共享、一栋、二栋验证适用范围及读写权限；对话和 UI 最终共用有效记录，完整知识编辑界面和历史内容迁移另排切片，不成为所有欢迎场景的新增前置。

在同一受控入口下接入负责人通过 default 或管理智能体分派任务的路径：保留真实发起人与委托范围，按登记职责选择执行者，持久创建任务并查询回执。先完成一个管理入口和一个执行智能体的合成闭环，再扩展其他入口，不为每个管理智能体重建调度服务。

验收：未发言的已关联成员也能识别；不能看到他栋背景；待确认者不误认；舍长只能指导本栋；撤权、离任、身份撤销后实际消费入口拒绝旧权限。先以测试适配器证明，不默认开启生产训练和外部消息。

身份验收补充同一人在两个 Gateway 中的统一识别与分别裁剪背景；分派验收补充任务已受理/已完成的区别、越权请求拒绝、委托撤销及目标暂不可用后的可恢复状态。
