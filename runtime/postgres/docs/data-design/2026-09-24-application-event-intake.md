# 申请回读与统一分派

日期：2026-09-24。迁移：`202609240004_application_event_intake.sql`，编号由总指挥预留。本切片只在模拟租户和显式本地开关下使用，不更改飞书 Workflow 或生产 Bridge 配置。

## 来源与版本

既有四老师签名 Unix Bridge 是唯一回调入口。

新模式默认关闭，固定配置资源别名及记录字段路径；

不从递归文本猜记录或修订。

启用后回调只持久唤醒记录回读，不运行旧制卡/直发脚本。

未启用配置仍保留原 jobs 消费方式。

新唤醒不受旧 delivery_id 永久去重影响，同记录第二次回调也可触发读取；

回调重复不等于内容变化。

来源适配器只读固定许可 Base/table 的指定记录，丢弃附件及不在用途白名单的字段。

回调中的姓名、付款、人员、订单、撤回标志、URL 和版本均不直接写成事实。

当前只允许本地模拟 HTTP 来源，不使用生产 Token；

正式飞书接线另行验证。

`welcome_applications`
继续是唯一申请投影，revision 为内部观察版本：仅许可内容 hash 变化时增加，不冒充飞书源版本。

源自身版本如可读取仅保存为来源证据，不用回调 ID 或时间推断顺序。

每次回读先在共同服务领取新 read_token，写入时校验该 token、绑定版本和原 revision；

后发读取使旧 token 失效。

冲突必须重新读取来源，不能把旧响应换 token 重交。

同 token 丢 ACK 后可以重交相同内容；

新回调读取到相同内容不增加版本或重建事项。

## 关联、撤回与分派

004 只增加接收/派发状态，引用已有业务绑定及 welcome_applications，不创建人员或主申请副本。

来源回读不提供 Person；

身份字段 hash 未变保留已确认 Person，身份字段变化则清除本申请的 Person 投影、解除关联案例的 application_id 并记旧引用审计。

不会撤销独立成立的账号与 Person 关系或 PMS 实际入住人事实。

姓名、昵称、手机号均属身份字段；

缺值变化也算变化。

其他许可内容或展示同意变化会提升内部 revision，撤销旧内容产物依据并要求公共欢迎服务刷新确认。欢迎线负责其 identity_receipt/content_receipt 失效和重新确认，本适配器不实现第二套审核逻辑。

只有成功授权回读的明确业务撤回字段可使 valid=false。

404、权限失败、暂时不可读或网络异常均保留原投影和待回读状态；

本地切片不推断物理删除。

撤回只停止未完成来源待办，不取消 PMS 已提交事实、不撤销独立执行账本、不伪造财务结果。

每个申请保留独立岸岸办理与四老师运营事项，内容变化更新原事项并追加审计；

已完成事项不会因回调被自动重新执行。

任务只有申请引用、版本、hash 和待核对状态，没有资料全文、证件、电话、附件地址或业务批准。

可靠的申请/实际住宿案例关联成立后，才由服务端持久 welcome_event 调用既有 welcome_review_open_task 公共入口。

同名、单候选、付款金额不能形成关联。

## 验证与停用

### 申请、对话与付款办理汇合

原岸岸申请事项可承接受权对话中的业务动作；来源只提供事项归属，不代替人类业务确认。相同申请事项的订房阶段保留唯一未确定失败或已完成动作；修订、换消息、并发或重启均返回原动作或要求先处理原动作，UNKNOWN 不换键。相同 PMS
quote 的重复订房也复用原动作，不以姓名、Person、金额或代付款人匹配事项。

已有对话订房时，link 工具先根据原成功动作读取当前 PMS 订单，返回来源与订单可读摘要。

宿主把具体来源、动作、申请修订、订单版本和操作者/会话绑定为短期待确认提议；有权人在该对话回复“确认关联”时，只有一个有效提议才绑定批准，模型传入的正文、摘要、readback 或 approved 不生效。

当前订单或申请变化使旧确认失效；“取消关联”清除当前对话自己的待确认提议。

内部 UUID 由工具传递，不要求员工手输。

精确 UUID 句式仅保留为本地验收入口，不作为运营前提。

服务端核对当前租户/绑定/范围、可信对话证据、持久 PMS 成功回执和实际当前订单回读，并在同一事务锁定来源与目标；已含独立动作的来源事项拒绝迁移。

映射保留在既有 work_items.metadata 并写一次事件审计，重复提交返回原结果，原申请与支付回执不改归属，不新增迁移或改001—004。

之后的操作沿该可靠事项处理，并核对订单ID；付款仍需实时读取原bill并逐笔确认，不因关联获得收款批准。

原事项各阶段独立记账，关联来源只显示办理状态；来源修订不能重放订房，明确撤回不取消已提交PMS事实。

同人另次住宿使用不同来源事项/quote，不自动合并。

### 已有住宿案例的欢迎交接

宿主在每次成功回读后，以相同固定来源/记录调用
`reconcile_welcome`，模型不传案例或产物引用。服务端只选择已可靠关联该申请、同来源/物业/范围、已准入且仍有当前住宿安排的案例。缺关联、未配置确认范围或申请撤回时保持明确待办状态，不以候选相似度自动认人。

现存关联要求申请、案例、有效 PMS occupant 身份链接指向同一 active
Person，链接版本与案例保留版本相等；撤销或失效的链接不交接。已有 welcome_event 引用发生冲突时拒绝，不通过更新 payload 改写原事项范围。

同案例/申请复用持久 anan
`welcome_event`，payload 的 tenant/scope/case/application 引用全部来自数据库；有效产物同样从绑定表取。然后调用已有
`welcome_review_open_task(None, &ReviewOpen)`，不调用渲染、发布或外发。

回读与欢迎交接是独立事务；交接失败保持 Bridge 唤醒待重试，下次先重新读取来源，再幂等重开同事项。

身份确认、内容确认及发布权限仍由公共欢迎服务分别校验；本适配器不接受模型提供确认。

共同欢迎快照通过 `Store::application_identity_basis(&mut tx, scope, application)`
读取可信身份依据，返回可选 hash；

模型和 ReviewOpen 不传此值。

该函数核对 tenant、有效 binding/version/scope、source/property/resource/record 归属，并用当前申请摘要、有效状态、同意状态与保存的身份摘要/源版本重算已提交 completed_hash。

其他来源写入者改变投影后，旧身份依据不可继续被误认作当前回读。

004 已应用后不改写迁移校验和。

验证重复回调与修订、并发回读 CAS、旧响应拒绝、丢 ACK 重放、内容自写忽略、撤回与暂时不可读、身份确认保留/失效、双消费者事项去重、未启用旧路由兼容和无外发。

生产修改/撤回触发、真实群可信交互、真实字段映射仍需独立验收。

停用新模式前先保留未完成唤醒、投影与事项；

不将积压申请转给旧制卡直发路径重放。

### T09 人工 PMS 接手的效果核验

沿既有 business_actions.readback 保存接手时实际 PMS 订单版本及已有财务事实 ID，不新增迁移。

插件先取共同服务指定的订单并实际回读，再原子进入 manual_handoff；重复接手保留第一次基线，未知/在途动作仍须先恢复。

基线缺失时拒绝自动认定完成。

人工回报仍需同会话可信消息指明订单。

核验必须晚于接手，符合原具体预览，并来自同物业/订单的新证据。

入住、退房、取消、改期、续住、缩住、换房，均比较 PMS 不可变 amendment 的类型和完整 payload；核验版本链、命令 ID、记录时间和唯一匹配，不以当前日期/房间/状态替代原效果。

有明确流水引用的 RECORD_COLLECTION 同时核对原预览的订单、方式、金额、币种、流水和新增 fact/command
ID；拒绝已冲正、已转出、旧事实及多义匹配。无唯一流水的收款不按同额猜同笔。CREATE_ORDER 不凭不完整回读证明原预览执行；采用下述独立人工承接决定，禁止越权读取其他员工专属回执。

完整历史只经宿主内部投影用于校验，不进入模型输出或错误正文。成功仅保存最小证据引用并完成原动作，不重放 PMS。验证含 PG 旧历史/伪相等/并发/重启与重复接手，以及实际 PMS
HTTP 人工操作路径；全部限任务自有本地库，不触及生产或保留支付库。

无流水现金补充（总指挥依据既有T09授权确定实施路径）：现有 collectionFacts 足够呈现具体新事实，因此不等待 PMS 新写入字段。

宿主将唯一符合原方案、晚于接手且仍有效的事实，连同订单/方式/金额/币种/时间展示为只读核对提议；有权人在同会话明确确认“确认这笔人工收款是本事项的办理结果”后，重新回读并核验原具体事实与版本。

确认绑定人、会话、动作及事实，不授予收款写入权。

多候选不猜测。

完整可信回报若已准确指明具体 fact 且所有效果核验通过，直接采用该回报，不重复确认；通常交互不要求输入内部 UUID。

旧提议、冲正或转出均失效。

PMS 当前 effectHash 包含 effect 与 basisVersions，不能预设跨预览业务相同就同 hash。PMS 只读评估已确认无需本轮新增接口；现有订单资料用于人工采纳，不依赖 hash 跨预览相等。

CREATE_ORDER 人工承接（总指挥依据既有T09授权确定实施路径）：不新增 PMS 接口。

岸岸可从权限内的订单查询选取具体订单；宿主重新 GET，将物业、订单版本、必要住客辨识、当前房间/日期/渠道/合同金额和原方案并列，列明差异。

有权人回复“确认此订单承接原订房事项”后，重新回读相同关键事实，持久记录原方案版本、订单事实、确认人和时间及人工采纳决定，结束原订房等待。

不伪造原 PMS 执行回执，不自动认人、收款或入住。

模型只选择候选订单，不能提交事实或批准。

宿主确认限定当前唯一未过期提议，绑定人/会话/事项/订单/原方案。

版本或关键事实变化需重审，缺事实、越权、其他事项已绑定该订单或同一订单有并行承接提议时拒绝。

UNKNOWN/在途不得进入人工承接。

旧原话未准确覆盖具体订单及差异不当作批准；已经确认且未变化的同一提议不会重复要求批准。

与严格相等的历史效果核验分别审计。
