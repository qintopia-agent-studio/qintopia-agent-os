# 申请回读与统一分派

日期：2026-09-24。迁移：`202609240004_application_event_intake.sql`，编号由总指挥预留。本切片只在模拟租户和显式本地开关下使用，不更改飞书 Workflow 或生产 Bridge 配置。

## 来源与版本

既有四老师签名 Unix Bridge 是唯一回调入口。

新模式默认关闭，固定配置资源别名及记录字段路径；

不从递归文本猜记录或修订。

启用后回调只持久唤醒记录回读，不运行旧制卡/直发脚本。

未启用配置仍保留原 jobs 消费方式。

新唤醒不受旧 delivery_id 永久去重影响，同记录第二次回调也可触发读取；

回调重复不等于内容变化。

来源适配器只读固定许可 Base/table 的指定记录，丢弃附件及不在用途白名单的字段。

回调中的姓名、付款、人员、订单、撤回标志、URL 和版本均不直接写成事实。

当前只允许本地模拟 HTTP 来源，不使用生产 Token；

正式飞书接线另行验证。

`welcome_applications`
继续是唯一申请投影，revision 为内部观察版本：仅许可内容 hash 变化时增加，不冒充飞书源版本。

源自身版本如可读取仅保存为来源证据，不用回调 ID 或时间推断顺序。

每次回读先在共同服务领取新 read_token，写入时校验该 token、绑定版本和原 revision；

后发读取使旧 token 失效。

冲突必须重新读取来源，不能把旧响应换 token 重交。

同 token 丢 ACK 后可以重交相同内容；

新回调读取到相同内容不增加版本或重建事项。

## 关联、撤回与分派

004 只增加接收/派发状态，引用已有业务绑定及 welcome_applications，不创建人员或主申请副本。

来源回读不提供 Person；

身份字段 hash 未变保留已确认 Person，身份字段变化则清除本申请的 Person 投影、解除关联案例的 application_id 并记旧引用审计。

不会撤销独立成立的账号与 Person 关系或 PMS 实际入住人事实。

姓名、昵称、手机号均属身份字段；

缺值变化也算变化。

其他许可内容或展示同意变化会提升内部 revision，撤销旧内容产物依据并要求公共欢迎服务刷新确认。欢迎线负责其 identity_receipt/content_receipt 失效和重新确认，本适配器不实现第二套审核逻辑。

只有成功授权回读的明确业务撤回字段可使 valid=false。

404、权限失败、暂时不可读或网络异常均保留原投影和待回读状态；

本地切片不推断物理删除。

撤回只停止未完成来源待办，不取消 PMS 已提交事实、不撤销独立执行账本、不伪造财务结果。

每个申请保留独立岸岸办理与四老师运营事项，内容变化更新原事项并追加审计；

已完成事项不会因回调被自动重新执行。

任务只有申请引用、版本、hash 和待核对状态，没有资料全文、证件、电话、附件地址或业务批准。

可靠的申请/实际住宿案例关联成立后，才由服务端持久 welcome_event 调用既有 welcome_review_open_task 公共入口。

同名、单候选、付款金额不能形成关联。

## 验证与停用

### 已有住宿案例的欢迎交接

宿主在每次成功回读后，以相同固定来源/记录调用
`reconcile_welcome`，模型不传案例或产物引用。服务端只选择已可靠关联该申请、同来源/物业/范围、已准入且仍有当前住宿安排的案例。缺关联、未配置确认范围或申请撤回时保持明确待办状态，不以候选相似度自动认人。

现存关联要求申请、案例、有效 PMS occupant 身份链接指向同一 active
Person，链接版本与案例保留版本相等；撤销或失效的链接不交接。已有 welcome_event 引用发生冲突时拒绝，不通过更新 payload 改写原事项范围。

同案例/申请复用持久 anan
`welcome_event`，payload 的 tenant/scope/case/application 引用全部来自数据库；有效产物同样从绑定表取。然后调用已有
`welcome_review_open_task(None, &ReviewOpen)`，不调用渲染、发布或外发。回读与欢迎交接是独立事务；交接失败保持 Bridge 唤醒待重试，下次先重新读取来源，再幂等重开同事项。身份确认、内容确认及发布权限仍由公共欢迎服务分别校验；本适配器不接受模型提供确认。

共同欢迎快照通过 `Store::application_identity_basis(&mut tx, scope, application)`
读取可信身份依据，返回可选 hash；

模型和 ReviewOpen 不传此值。

该函数核对 tenant、有效 binding/version/scope、source/property/resource/record 归属，并用当前申请摘要、有效状态、同意状态与保存的身份摘要/源版本重算已提交 completed_hash。

其他来源写入者改变投影后，旧身份依据不可继续被误认作当前回读。

004 已应用后不改写迁移校验和。

验证重复回调与修订、并发回读 CAS、旧响应拒绝、丢 ACK 重放、内容自写忽略、撤回与暂时不可读、身份确认保留/失效、双消费者事项去重、未启用旧路由兼容和无外发。

生产修改/撤回触发、真实群可信交互、真实字段映射仍需独立验收。

停用新模式前先保留未完成唤醒、投影与事项；

不将积压申请转给旧制卡直发路径重放。
