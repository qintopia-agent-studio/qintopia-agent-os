# 岸岸工作账号授权

日期：2026-09-26。领域：Person/Agent 共同身份与客房办理。岸岸是小客服岗位的智能副驾。可信企微来源中的稳定账号标识可指向已核验的
`work_accounts`，包括多人共用账号；共用账号不对应虚构 Person，也不识别背后的员工。

## 目标与范围

复用
`source_identity_links`、`person_identity_gateways`、`work_accounts`、`collaboration_scopes`、`business_property_bindings`、`business_operation_grants`、共同配置版本及
`work_items`。账号授权绑定一个有效物业、岗位业务角色（operator/admin）和明确的
`operations.json` 操作集合。角色仅用于该物业的岸岸业务显示与审计，不授予 Agent
OS 配置管理权。已有自然人授权路径保留；账号授权与自然人授权不相互继承。

工作账号仅由岸岸 PMS 工具入口解析为业务主体；共同 Person 会话入口继续拒绝共用账号，欢迎审核使用其独立的工作账号主体校验。

生产企微宿主首次观测只形成待登记来源。独立的 shared 网关命名空间经可信观测及管理者登记后，PMS 采集入口才将有效工作账号视为已确认。

停用或来源、网关版本变化后重新拒绝。自然人确认仍遵循原 Person 核验流程。

账号重新登记后，旧版本消息不能按新版本身份重放；新消息须重新形成证据。

有权管理者只可从独立 `shared`
网关中可信来源的已有观测登记工作账号，不通过显示名或聊天文字创建身份。普通 `employee`
网关下尚未绑定 Person 的待确认身份仍走自然人核验，不能作为岸岸工作账号候选、注册来源或业务主体。

配置采用原管理服务会话、事务预览、版本校验、幂等键和审计。

账号停用、来源或网关变更、物业停用、操作撤权及授权过期均立即阻止后续执行。

所有外部执行前按当前账号和操作重新校验；待确认方案还须匹配原账号、来源消息、当前方案及有效时间。共享工作账号暂停本物业的 PMS 工作提醒须另获
`pms.reminder.snooze` 操作授权；其他 PMS 执行授权不隐含提醒管理权。此键只控制 Agent
OS 内的提醒状态，不对应 PMS 命令或外部发送。

工作台沿组织关系中的管理范围进入「物业业务授权」二级视图；关联岸岸客房职责的岗位详情可提供同一入口。`/api/business`
按当前 `Policy::manager` 返回可管理范围及 `read_business`/`execute_business`
管理能力，即使范围尚无物业绑定也可发现。每次只展示选中范围的物业、工作账号和候选，授权、撤权及停用入口按该范围能力列出。此只读元数据不授予权限；预览和保存仍在同一锁定事务按当前管理 grant、范围和账号版本重新核验。仅持业务
`admin`
角色或执行 grant 而无对应管理 grant 的人员不可注册、停用账号或授撤权。配置响应在 SQL 查询时先限定当前可管理范围与可见操作，再执行 256 项上限；其他范围的存量数据不能耗尽当前管理者的页面容量。

每个工作账号的 `can_disable`
是只读界面提示：仅当管理者对该账号所有未撤销操作授权对应的管理动作均有权限时为真，包括当前列表未展示的操作授权。撤权后按现行授权重新计算；停用命令仍在事务内独立重验，不能依赖该提示授权。

每笔收款要求对订单、流水和金额的明确交办或确认；收款事件、预览或 PMS
Token 权限均不构成人类确认。原请求键和 UNKNOWN 状态不得换键重放。

同一物业、操作、方式和流水命中旧版本工作账号的动作时，明确拒绝为主体冲突；不返回旧动作为当前账号的重放，也不创建第二个动作。旧动作、UNKNOWN 状态及原执行键保留待授权恢复或人工核实。

同一订房事项或报价标识命中旧版本账号动作时也拒绝重放旧动作。旧版本动作不能作为新版本账号认领工作事项或选择待确认方案的依据；独立的收款事件及申请来源仍按各自当前证据校验。

后续预览、确认与执行也保持动作原始主体类型边界：工作账号不可接续旧 Person 动作，Person 不可接续工作账号动作。

初始名单保留在仓库外受限文件。名称仅用于定位，首次启用需核对可信渠道稳定账号标识及真实管理账号的认证条件；空授权默认拒绝，不提供 LOCAL 开关或 SQL 自授权。浏览器生产入口需有实际认证和受限监听，不复用模拟租户。

## 迁移与回退

拟新增
`202609260001`，不改写旧迁移。对现有业务操作授权和证据表增加可空工作账号主体与互斥约束，保留历史 Person 行；

账号授权仍使用原物业绑定与操作表。配置停用通过撤权保留历史。

回退优先停用生产入口与账号授权，保留动作、确认及 UNKNOWN 恢复数据；不删除迁移后的审计。

## 验证

隔离 PostgreSQL 验证可信账号解析、共用账号办理、冒名与跨物业拒绝、新增/停用/撤权、跨版本同流水、订房事项及旧工作事项拒绝且原 UNKNOWN 动作保留、方案变化/过期/重复确认和 UNKNOWN 原键恢复；再跑 Sidecar/能力包专项与
`pnpm check:pr:auto`。真实企微、PMS 和生产部署留待有权人员逐项验收。
