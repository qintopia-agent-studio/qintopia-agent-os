# 本栋文本约定生命周期

Owner: Agent OS / sidecar。仅隔离合成环境，不启用生产、真实模型或外发。

在已有 Space 定义版本、collaboration knowledge
items/revisions、WorkItem 与共同授权上补齐文本约定生命周期。UI 与本地对话使用同一服务。结构化欢迎规则保留其专用消费者和原版本回退语义。

## 状态与时间

追加迁移 `202609230008_person_rule_lifecycle.sql`。knowledge items 新增
`lifecycle_managed`（默认 false）和
`stopped_at`。只有本次文本生命周期服务维护的项目启用新语义，不改变既有结构化事项。

新语义按最新已到开始时间、未撤回的版本确定当前约定，再判断截止时间；该版本到期后整项不再适用，不回退旧版。未来版本在开始前不覆盖当前版本；明确取消未来版本才移除该次排期。修改未来版在同一事务中撤回旧排期并新增替代版本。开始/结束均在服务端校验。

停止整项会撤回全部当前和未来版本，记录 stopped_at，递增 item
version；先前排队请求的预期版本因此失效。重新启用是明确的新请求，不能由旧请求、刷新或迟到审批自动恢复。内容版本和历史不物理删除。

## 操作与审核

新增/修改、替换未来版、取消未来版、停止整项共享 change_rules 授权及租户事务锁。自主权限立即执行；需指定人确认时以完整不可变请求进入现有 WorkItem，最终执行重验身份、来源授权、确认人权限及知识版本。提交前先校验请求，不把非法日期或不存在的目标送去审批。

指定人可以核对具体内容后批准或拒绝，请求人可以撤销尚未完成请求。批准后由受控服务执行并显示真实结果，失效或冲突明确失败；不将“批准”冒充“已生效”。待办只显示本人请求或本人被指定审核的记录，仍受当前范围和有效权限约束。

已提交的文本约定请求独立于浏览器会话的退出或自然到期。执行仍核验提交时账号版本与当前账号状态；停用或重置账号、身份版本改变、撤回授权都会使旧请求失效。确认人的批准也保留相同账号版本依据。

新增 rule lifecycle
events 表仅保存操作审计（操作者、范围、知识项、动作和前后状态），内容事实仍以原 Space 版本为准。幂等回执沿用 collaboration_tool_receipts。事件与内容写入同一事务。

## 验证与恢复

隔离 PostgreSQL 覆盖新增与起止时间、未来替换/取消、停止后旧版/未来版/旧待办不复活、明确重新启用、版本冲突、跨栋、撤权、指定审核、拒绝/撤销、刷新后待办与历史。

UI 验证相同链路；浏览器不可用时单独标记，不能将接口或 DOM 替身当浏览器验收。

迁移仅追加字段和审计表，保留 006/007 原 checksum。回滚应用时停用新入口并保留数据库；旧代码不了解生命周期字段，不允许直接回退旧规则消费者继续运行，否则会恢复旧版回退行为。恢复须使用理解新语义的固定版本。
