# 工作台个人账号与可信会话

Version: `2026-09-18.001`。Owner: Agent OS / sidecar。仅隔离本地验收。

复用现有 Person、任职与授权；追加账号、服务端会话、登录限流表，不修改旧迁移。账号以 tenant +
person_id 唯一关联已有已核验人员，并固定明确的来源身份引用，不按姓名匹配，不创建 Person，不授予业务权。用户名限 ASCII、大小写归一。密码使用 RustCrypto
Argon2id PHC（随机盐，19
MiB、2 次、1 并行度），最少 12 字符、最多 128 字符。密码与会话凭据不进入日志和审计；审计只存账号、人员、操作引用。

使用服务端不透明随机会话：客户端持有随机值，数据库只存 SHA-256 摘要，8 小时绝对到期；HttpOnly
/ SameSite=Strict。当前只监听 loopback HTTP，生产 HTTPS、Secure
cookie、代理部署及运维验收不在本轮放行范围。所有 POST 校验精确 Origin、JSON 类型；拒绝未知字段、重复头及跨站请求，登录也执行同样检查。数据库持久限流同时限制整个入口及归一用户名，15 分钟窗口，分别 60
/ 5 次。

可信边界：登录会话解析得到账号绑定 person_id 与来源身份版本，生成不可由 JSON 构造的 Actor。每次 Store 事务在租户锁内同时验证会话、账号和身份，再读取当前授权。

修改密码、管理员重置、停用账号原子撤销所有旧会话；任职与授权沿用实时策略，不写入登录缓存。synthetic 租户和 loopback
qintopia_test 门禁保持，旧固定操作者入口只保留为明确的历史测试适配，新的密码入口不能回退到它。

账号管理员须在组织根范围持有 default / organization /
identity 的管理授权，并重验完整来源链，普通登录、岗位名称或其他管理权限均不成立。账号列表与开通候选仅向此授权开放；开通账号不改变任职。首次初始化仅受控本地 CLI：显式指定已有 person_id、用户名，从标准输入读取口令，空账号租户中核验其已有组织身份管理权，只开通该账号。无公开注册、领取管理员或自动提升权限接口。

工作台沿用组织关系 / 配置任职与范围 / 基础台账；普通任职可查看自己的有效连接，管理人员按授权范围查看和操作。受限用户不返回其他范围人员、群或台账。账号管理作为独立页面入口；无权限登录显示空工作范围，可修改密码和退出。

验证复用业务测试框架、真实 PostgreSQL 迁移与 Store/HTTP，登记密码、会话、跨范围、账号越权、撤权、限流和 CSRF 场景，检查拒绝无业务数据泄露或写入。演示用新合成库，不复用历史 checksum 已不同的旧库。回滚关闭本地进程，保留追加表和审计，不恢复已撤销会话，不删除旧任职或历史。

密码会话重放已完成配置命令时，只返回“已处理，请重新读取当前状态”，不返回旧审计载荷，也不重复执行。历史合成测试适配仍保留原有幂等返回契约。
